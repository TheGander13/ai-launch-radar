# 📡 AI Launch Radar

**Демо:** https://ai-launch-radar.vercel.app

Веб-сервіс для пошуку нових AI-стартапів на основі публічного API [FreeSerp](https://freeserp.ai/docs.php) (`index=sites`, ніша AI). План сайту (мета, аудиторія, сторінки, структура, SEO) — у [PLAN.md](PLAN.md).

## Що зроблено
- **Radar** — стрічка справжніх AI-продуктів (`ai_startups=1`): пошук, фільтри за нішею (15 ніш), стеком, Domain Rating, сортування, «Load more».
- **Built with AI** — сайти, зібрані на Lovable, v0, Bolt, Base44 (`ai_source`), з кількістю сайтів по кожному конструктору.
- **Compare** — порівняння до 3 сайтів у таблиці (ніші, стек, DR, дати, сервер, опис) + «Find similar» — конкуренти в тій самій ніші.
- **Статистика індексу** з `?stats=1` (кількість AI-стартапів, топ-ніша, нові сайти за 7 днів).
- Стан фільтрів зберігається в URL — вибіркою можна поділитися посиланням.
- SEO-основа: title/description, Open Graph, schema.org `WebApplication`, семантична розмітка, aria-атрибути.
- Адаптив під мобільні, скелетони під час завантаження, обробка помилок і порожніх станів, скасування застарілих запитів, debounce пошуку.
- Безпека: весь контент з API екранується (захист від XSS), посилання лише `http/https`.

Стек: чистий HTML + CSS + JavaScript без збірки й залежностей. Хостинг — Vercel.

## Як запустити локально
Потрібен лише Python 3:

    python3 dev_server.py
    # відкрити http://localhost:8080

Відкрити `index.html` напряму як файл не вийде — запити до API йдуть через проксі (див. спостереження №1).

## Спостереження щодо API FreeSerp
Знайдені під час розробки — можливо, будуть корисні команді.

1. **CORS не працює в браузері через дубльований заголовок.** Сервер повертає `Access-Control-Allow-Origin: *` двічі; браузер склеює їх у `*, *` і блокує відповідь, хоча в документації API заявлено як CORS-open. Перевірка:

        curl -s -D - -o /dev/null -H 'Origin: http://localhost:8080' 'https://freeserp.ai/api.php?size=1' | grep -i access-control

   Ймовірно, заголовок додають і PHP, і nginx/Cloudflare — достатньо прибрати один. У проєкті обійдено через same-origin проксі (`vercel.json`, `dev_server.py`).
2. **Затримка даних.** Найсвіжіший `went_live` в індексі — 8 вересня 2026, тоді як поточна дата — 2 жовтня; `stats.ai_startups.today` = 0. Тому фільтр «за останні N днів» за замовчуванням не використовується, а плитка «сьогодні» при нулі замінюється топ-нішею.
3. **`dr` у нових доменів відсутній** — поле не приходить зовсім (а не `null`, як у документації). В інтерфейсі показується «DR —».
4. **`ai_startups=1` пропускає не лише стартапи** — у видачі трапляються агенції (`quartzdevelopment.site`, `mzkmcreator.tech`, `the360tech.com`) і лендинг FlipHTML5 (`carpetonebyhenry.com`). Схоже, достатньо однієї «стартапової» ніші серед кількох. Можливе покращення — враховувати основну (першу) нішу. Також у `top_ai_categories` першою йде «Other AI», яку документація вважає шумом.
5. **Блокувальники реклами.** uBlock Origin Lite блокував один із прямих запитів до `api.php` (`ERR_BLOCKED_BY_CLIENT`). Через проксі на власному домені проблема зникає.

## Що не встиг / що зробив би далі
- **SSG/SSR-сторінки під SEO** (Next.js + ISR): `/niche/{slug}`, `/site/{domain}`, `/compare/{a}-vs-{b}`, `sitemap.xml` — детально в PLAN.md.
- **Власний фільтр шуму** (агенції, магазини) поверх `ai_startups=1`.
- **Index `web`**: на картці сайту — свіжі згадки про нього в інтернеті.
- **Email-дайджест** нових стартапів у вибраних нішах.
- E2E-тести (Playwright) і кешування відповідей на edge.

## Як я працював з AI
Інструмент — **Claude (Anthropic)** у застосунку Claude. Формат — парне програмування: Claude аналізує, пропонує рішення і дає команди, я виконую їх у терміналі, перевіряю результат і вирішую, що робимо далі. Весь проєкт — близько 1 години.

**Правила, які я задав AI:**
- Спочатку аналіз, потім рішення. Жодного коду до вивчення документації і живого запиту `curl`.
- 1–2 команди за крок, після кожного — перевірка виводу.
- Мінімальні точкові патчі замість переписування файлів; патчі з перевіркою (`assert`) — якщо рядок не знайдено, файл не змінюється.
- Ручне тестування в браузері після кожного етапу: desktop + емуляція iPhone 14 Pro Max, консоль DevTools.

**Ключові промпти (стисло):**
1. «Ось тестове завдання (скриншоти). Що скажеш, які ідеї?» — Claude вивчив документацію API, запропонував 3 ідеї та комбінацію.
2. «Робимо твою ідею. Працюємо через термінал: ти даєш команди, я вставляю, все контролюю і перевіряю. Пара команд — перевірка — далі».
3. «Ці спостереження, якщо вони на їхньому боці, треба розписати і вказати їм?» — так з'явився розділ про API вище.
4. «Нічого не знаходить» + скриншот консолі — знайдено дубльований CORS-заголовок, додано проксі.
5. «Начебто все працює» + скриншоти desktop/mobile — AI помітив горизонтальний скрол на мобільному, «0» у статистиці та нішу «Other AI»; виправлено.

**Де довелося контролювати AI:** одна з команд містила вкладений блок коду, через що вона обрізалась при копіюванні, і термінал завис у `heredoc>`. Помилку помітив за виводом, команду перегенерували без вкладених блоків. Тому кожен крок перевіряється перед наступним.
